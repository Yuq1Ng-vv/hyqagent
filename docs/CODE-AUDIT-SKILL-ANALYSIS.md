## 一、概述

这是一篇关于 AI 代码审计 Skill 的系统工程化方案。它不是一个 prompt 模板的分享，而是一个完整的审计系统设计——覆盖了防幻觉、多轮增量扫描、Agent 合约、覆盖率驱动机

制、攻击链分析等全套架构。

与 HyqAgent 的核心哲学对比：

| 维度 | 文章方案 | HyqAgent |
|------|---------|----------|
| Ground Truth | 文件读取日志（工具调用记录） | CPG 图（AST/CFG/DFG） |
| 防幻觉策略 | Prompt 规则 + Agent 合约（程序性） | CPG 架构级隔离（架构性） |
| 扫描驱动 | LLM 自由探索 + 矩阵查漏 | 确定性先行 + LLM 补充 |
| Agent 模式 | 多 Agent 并行 + 合约约束 | 单 Agent + 丰富工具 |
| 覆盖率保障 | 10 维度手工矩阵 | 200 项 ASVS 对齐检测矩阵 |

## 二、核心设计哲学

### 2.1 防幻觉：宁可漏报，不可误报

三条结构性硬规则：

1. **禁止猜测文件路径** — 必须用 Glob/Read 验证文件存在
2. **禁止编造代码片段** — 必须引用 Read 工具实际输出的代码
3. **禁止报告未读文件中的漏洞** — 报告中每个文件必须在读取日志中可追溯

这些规则的共同点：**不依赖 LLM 自觉，而是可以通过工具中间件强制执行。**

### 2.2 反确认偏见：方法论驱动

- 禁止"基于之前的审计经验"式推理
- 禁止因为漏洞类型"看起来不太可能"就跳过
- 必须枚举所有敏感操作，然后逐一验证
- 检查清单必须完整执行，每个维度一视同仁

### 2.3 攻击链思维：漏洞不是孤岛

```
认证绕过(H) + 需认证的 SSRF(M) = 未认证 SSRF(C)
信息泄露(L) + 密码重置逻辑缺陷(M) = 账户接管(C)
```

## 三、审计架构：五阶段模型

```
Phase 1: Reconnaissance（侦察）
    ↓
Phase 2A: Vulnerability Hunt（自由审计）
    ↓
Phase 2B: Coverage Verification（覆盖率自检）
    ↓
Phase 3: Deep Dive（深度验证）
    ↓
Phase 4: Report（报告生成）
```

与 HyqAgent 5 阶段流水线的映射：

| 文章 Phase | HyqAgent 等价 | 差距 |
|-----------|--------------|------|
| Phase 1: Recon | CPG Engine (AST/CFG 解析) | HyqAgent 更强（确定性），但缺少"枚举攻击维度"步骤 |
| Phase 2A: Hunt | Scanner Pipeline (stages 2-4) | 文章用多 Agent 并行，HyqAgent 用单 Agent |
| Phase 2B: Coverage | **缺失** | 关键 gap——HyqAgent 没有"扫完后自检覆盖"的步骤 |
| Phase 3: Deep Dive | **缺失** | HyqAgent 没有对高价值发现的独立验证深度 |
| Phase 4: Report | Report 模块 | HyqAgent 缺少置信度分级和攻击链合成 |

### 关键设计决策

1. **自由审计在前，检查清单在后** — LLM 先不受约束地探索，再用矩阵查漏。如果反过来，LLM 就变成了清单执行器，失去发现非常规漏洞的能力。
2. **Agent 分工动态决定** — Phase 1 的攻击面分析决定 R1 有多少 Agent、各自负责什么维度，不是预定义的。
3. **覆盖率是验证工具，不是驱动引擎** — Checklist 的角色是"安全网"而不是"方向盘"。

## 四、增量补漏：R2 不重复 R1

### 跨轮传递结构

```
R1 完成后产出的结构化状态：
  COVERED:   {维度 → 发现数}         ← R2 跳过
  GAPS:      {维度 → 未覆盖原因}       ← R2 重点攻击
  CLEAN:     {确认无漏洞的搜索方向}     ← R2 跳过
  HOTSPOTS:  {高价值待追踪点}          ← R2 深入
  FILES_READ:{已读文件列表}            ← R2 不再重读
  GREP_DONE: {已执行的搜索模式}        ← R2 不再重搜
```

### Token 效率

| 轮次 | Agents | Turns/Agent | 发现数 |
|------|--------|-------------|--------|
| R1 | 5 | 25 | 51 |
| R2 (naive) | 5 | 25 | ~51（重复） |
| R2 (with state) | 3 | 20 | 12（新） |

R2 节省约 52% token，且 12 个新发现不是重复项。

### 对 HyqAgent 的启示

CPG 图天然就是预计算的跨轮状态——代码解析一次，所有轮次共享同一张图。不需要像文章那样做文件级 skip-list，可以直接做图级别查询缓存。

## 五、Agent 合约

10 条规则分为两类：

### 结构性规则（可被工具中间件强制执行）

| # | 规则 | 类型 |
|---|------|------|
| 1 | 搜索路径限制 | 可执行 |
| 2 | 工具调用次数上限（≤50） | 可执行 |
| 3 | Bash 调用 ≤10 次 | 可执行 |
| 4 | Turn 预留（最后 3 turns 停止探索） | 可执行 |
| 5 | Sink 类别上界（每维度 ≤8 类，每类 ≤3 个实例） | 可执行 |
| 6 | 输出格式符合模板 | 可验证 |

### 行为规则（依赖 LLM 遵从）

| # | 规则 | 类型 |
|---|------|------|
| 7 | 先枚举所有敏感操作再逐一验证 | 行为性 |
| 8 | 同类漏洞 ≥5 个合并报告 | 行为性 |
| 9 | 数据转换管道追踪 | 行为性 |
| 10 | 禁止猜测文件路径（验证后才能引用） | 行为性 |

**关键洞察**：可强制执行的规则影响审计质量不如行为规则大，但行为规则的强制难度最高。"胶囊模式"让 Agent 在边界内自由，但边界是硬约束。

## 六、置信度分级

| 等级 | 条件 | 可报最高严重度 |
|------|------|---------------|
| 已验证 | 完整数据流 + 无有效防护 + 可构造 PoC | Critical |
| 高置信 | 完整数据流 + 无有效防护，但 PoC 需特定环境 | Critical/High |
| 中置信 | 数据流不完整，或防护可绕过性不确定 | Medium |
| 需验证 | 仅 Grep 命中模式，未追踪数据流 | Low/Info |

### Critical/High 必须有数据流

核心逻辑：LLM 编造漏洞声明容易，但编造一条从真实 source 经过真实中间函数到真实 sink 的完整数据流很难。这是一个**工作量证明门槛**。HyqAgent 的 CPG 可以直接确定性验证这个路径是否存在——比文章方案更可靠。

## 七、实战案例

- **目标**：~200K 行 Java，Spring Boot 3.x BI 平台
- **R1**：5 Agent × 25 turns = 51 findings
- **R2**：3 Agent × 20 turns = 12 new findings
- **结果**：12 个 Critical 漏洞（包括 JWT 签名验证缺失 CVSS 9.1、权限注解无 AOP 实现 CVSS 9.8 等）

## 八、文章踩过的坑

### 坑 1：Agent 输出截断

Agent 最后一个 turn 还在搜索 → 输出超长被截断 → HEADER 和发现表格全部丢失。
**修复**：Turn 预留规则 + HEADER 前置 + 哨兵机制。

### 坑 2：R2 重复 R1 的工作

R2 Agent 不知道 R1 做了什么，重新搜索相同模式、重读相同文件。
**修复**：跨轮传递结构（COVERED/GAPS/CLEAN/HOTSPOTS/FILES_READ/GREP_DONE）。

## 九、对 HyqAgent 的改进建议

### 🔴 P0 — 立即落地（高影响、低复杂度）

#### 1. 覆盖率自检阶段

在 Phase 3（假设生成）之后，Phase 4（验证）之前，加一个 **Coverage Self-Check**：
- 用 `detection_matrix.json` 的 200 项做结构化自检
- 输出 GAPS（未覆盖的检测维度）+ HOTSPOTS（已有线索但未深追的点）
- 触发 R2（针对性补漏）

**实现**：`scanner/` 下新增 `coverage_checker.py`，纯确定性逻辑，不需要 LLM。

#### 2. CPG 驱动的置信度自动分级

`VulnerabilityHypothesis.confidence` 补充确定性规则：
- CPG 存在完整 source→sink 路径 → confidence ≥ 0.7
- CPG 不存在该路径 → confidence ≤ 0.3，自动降级为 MEDIUM
- 路径含 sanitizer → confidence × 折扣因子

**实现**：`scanner/validator.py` 的 `validate_deterministic()` 中加 30 行逻辑。

#### 3. 扫描前能力声明

Orchestrator 启动时输出确定性的能力矩阵：
```
此扫描将检测: SQL注入/命令注入/路径穿越/硬编码密钥/XSS(反射型)
部分检测: SSRF(仅sink-based)/反序列化(仅已知gadget)
无法检测: IDOR/业务逻辑/竞态条件/加密弱点
覆盖率: 134/200 项确定性检测, 43/200 项LLM辅助
```

**实现**：`scanner/orchestrator.py` 新增 `assess_capabilities()`，纯配置内省 ~50 行。

#### 4. CPG 查询缓存

同一 `find_path` 查询可能在不同假设中执行几十次。加基于查询哈希的缓存。

**实现**：`cpg/query.py` 新增缓存层 ~40 行。

### 🟡 P1 — 中期规划

#### 5. 攻击链分析模块

从 CPG 图中找"低权限入口 → 权限提升 → 高影响 sink"路径，用中等模型做组合分析。

#### 6. 多轮增量扫描

- 收敛条件检查 → 未达标 → 启动 R2
- R2 Agent 划分由 R1 的 GAPS 决定
- R2 不重复 R1 已确认干净的维度

#### 7. 结构化截断防御

所有 LLM 输出加哨兵标记：`---FINDING_START---` / `---FINDING_END---`。

### 🟢 P2 — 长期参考

#### 8. 多扫描模式

Quick / Quick-Diff / Standard / Deep —— 等覆盖扩大后再做。

#### 9. Agent 合约框架

在 `protocols.py` 中预留接口，不实现完整多 Agent 调度——保持单 Agent 路线。

## 十、HyqAgent 的优势与差距

| 维度 | 文章方案 | HyqAgent | 评语 |
|------|---------|----------|------|
| Ground Truth | 文件读取日志 | CPG 图 | HyqAgent 更强——结构化的，不需要日志追溯 |
| 防幻觉 | Prompt + 合约规则 | CPG 架构级隔离 | HyqAgent 更强，但缺少程序层防线 |
| 覆盖率 | 10 维度手工矩阵 | 200 项 ASVS 矩阵 | HyqAgent 更细，但缺少"自动查漏"机制 |
| 多轮扫描 | 跨轮状态传递 | 未设计 | **差距**——需要补 |
| Agent 控制 | 10 条 Agent 合约 | 单 Agent 路线 | 不同选择——HyqAgent 更保守 |
| 置信度 | LLM 估算 | CPG 可确定性验证 | HyqAgent 潜力更大——还没实现 |
| 攻击链 | LLM 推理 | CPG 图路径查询 | HyqAgent 潜力更大——更确定、更可复现 |
| 工程成熟度 | 实战验证过 200K 行项目 | 仅完成 CPG 基础层 | 阶段差异，不是方向问题 |

## 十一、应该拒绝的设计

1. **把防幻觉和污点分析做成 LLM Prompt 模块** —— HyqAgent 的防幻觉靠 CPG 架构，污点分析靠 taint_rules.yaml + CPG 查询。用 LLM 做这些是循环论证（用 LLM 防止 LLM 幻觉），不应采纳。

2. **10 维矩阵作为独立评分系统** —— HyqAgent 已有 VDR/EC/RWC/VCC/Ĉ 五个收敛指标，再加一套平行评分会导致混乱。矩阵维度应作为 Completeness Critic 的结构化提示问题，而非新指标。

3. **Phase 顺序重组** —— HyqAgent 的"确定性先行"阶段顺序不应改变。LLM 自由探索应在确定性扫描之后，作为补充机制而非主引擎。

---

## 十二、总结

这篇文章最值得学的是**"结构化约束"**的设计方法——如何用覆盖率矩阵、跨轮状态、Agent 合约，把 LLM 的非确定性能力装进审计系统需要的确定性框架里。

HyqAgent 最大的机会是：**CPG 图让"框架"天然更强**——图的拓扑结构可以直接替代文章依赖 LLM 做的覆盖率检查、置信度判断和攻击链推理。需要做的是：补上程序性防线层，并发挥 CPG 的结构化优势来改进当前设计中的缺失环节。

关键在于：**架构性防幻觉（CPG）+ 程序性防幻觉（工具中间件 + 跨轮状态）= 最强防线。**
